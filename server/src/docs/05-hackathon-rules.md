# Campus Hackathon Rules

## Team size

Teams are 2–3 students. One submission per team. No solo entries and no
teams larger than 3.

## Two-part structure

This event ships in two parts. The 70% baseline (this document pack) is
built before the event. A separate 30% problem statement is shared on
hackathon day itself and is not available ahead of time.

## Demo requirements

A local demo is fully accepted for scoring. A live AWS deployment is not
required — it only earns bonus marks.

## Judging areas

- Working sign up, login, and forgot-password flow
- Chat that answers only from the club documents and cites sources
- A safe fallback when the answer isn't in the documents
- A clear explanation of how the system would deploy on AWS
- A published Builder Center article with screenshots

## Conduct

All submitted work must be original. Credit any open-source libraries you
use. Be respectful in team channels and during judging — disruptive conduct
can result in disqualification.

## When you're unsure about a rule

Don't guess about scoring or deadlines. Contact the campus AWS Student
Builder contact listed in 01-onboarding-faq.md.
